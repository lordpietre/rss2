# 1. Manifiesto del canal

## PIETRE CONTRA LAS MÁQUINAS

P//M nace como un canal tecnológico que no pretende únicamente enseñar
herramientas.

El objetivo es observar la relación entre humanos y máquinas desde una
perspectiva crítica:

-   ¿La tecnología nos libera o nos convierte en piezas de un sistema?
-   ¿La inteligencia artificial aumenta nuestras capacidades o redefine
    qué significa pensar?
-   ¿La automatización mejora nuestra vida o elimina nuestra autonomía?
-   ¿La industria tecnológica vende progreso o simplemente vende
    dependencia?

El canal utiliza una estética antigua porque existe una contradicción
interesante:

Los ordenadores antiguos eran máquinas limitadas, transparentes y
comprensibles.

Las máquinas actuales son extremadamente potentes, pero cada vez más
opacas.

P//M explora ese choque.

------------------------------------------------------------------------

# 2. Universo narrativo P//M

El canal se presenta como una transmisión procedente de un sistema
llamado:

    COLOSSUS SYSTEM

COLOSSUS es una máquina antigua que analiza la tecnología del presente.

Cada vídeo es interpretado como un programa ejecutable:

    pietre@colossus:~$ ./014.bin

El archivo `.bin` representa una misión:

-   investigar una noticia;
-   analizar una tecnología;
-   desmontar una promesa;
-   enseñar un procedimiento;
-   registrar una anomalía.

------------------------------------------------------------------------

# 3. COLOSSUS: la máquina protagonista

COLOSSUS no debe ser una inteligencia artificial tipo asistente.

Es más parecido a un ordenador industrial antiguo.

Una máquina que:

-   recibe datos;
-   ejecuta análisis;
-   muestra resultados;
-   genera advertencias;
-   falla ocasionalmente.

Su personalidad se expresa mediante mensajes del sistema.

Ejemplo:

    COLOSSUS ANALYSIS

    SUBJECT:
    ARTIFICIAL INTELLIGENCE

    RESULT:

    TECHNOLOGY DETECTED

    HUMAN EXPECTATIONS:
    EXCESSIVE

    WARNING:
    MARKETING SIGNALS ABOVE NORMAL LEVEL

# 4. Filosofía audiovisual

## 4.1 La estética no es decoración

El CRT, el verde fósforo y la terminal no son solamente un estilo retro.

Representan una idea:

> La máquina era visible. Ahora la máquina se ha vuelto invisible.

Un ordenador antiguo mostraba:

-   memoria disponible;
-   procesos;
-   errores;
-   límites.

Los sistemas modernos esconden:

-   modelos;
-   datos;
-   algoritmos;
-   decisiones.

P//M utiliza una máquina antigua para hablar sobre máquinas modernas.

------------------------------------------------------------------------

# 4.2 Influencias conceptuales

La estética combina:

-   terminales Unix de los años 90;
-   estaciones de trabajo;
-   ordenadores industriales;
-   cultura hacker clásica;
-   ciencia ficción tecnológica;
-   crítica de la aceleración tecnológica.

La referencia no es "futuro brillante".

Es más cercana a:

-   sistemas heredados;
-   infraestructuras abandonadas;
-   máquinas que siguen funcionando después de décadas.

# 5. Tipos de vídeos

Cada formato tiene una identidad narrativa.

------------------------------------------------------------------------

# TRANSMISSION

## Noticias tecnológicas

Estructura:

    BOOT
    ↓
    RECEIVE SIGNAL
    ↓
    ANALYSIS
    ↓
    REPORT
    ↓
    ARCHIVE

Ejemplo:

    TRANSMISSION 021

    NEW AI MODEL DETECTED

    PROCESSING CLAIMS...

    RESULT:
    REQUIRES VERIFICATION

------------------------------------------------------------------------

# MACHINE

## Inteligencia artificial

Tema principal:

La relación humano-máquina.

Estructura:

    SYSTEM QUERY

    WHAT IS THE MACHINE?

    INPUT:
    PUBLIC CLAIMS

    PROCESSING...

    OUTPUT:
    ANALYSIS

------------------------------------------------------------------------

# PROTOCOL

## Tutoriales

Los tutoriales son tratados como procedimientos técnicos.

Ejemplo:

    PROTOCOL 004

    INSTALLATION PROCEDURE

    OBJECTIVE:
    DEPLOY LINUX SERVER

    STATUS:
    READY

------------------------------------------------------------------------

# TEST

## Experimentos

Ejemplos:

-   probar hardware antiguo;
-   instalar Linux en dispositivos raros;
-   comparar tecnologías.

Formato:

    TEST SUBJECT

    INITIAL CONDITION

    PROCEDURE

    RESULT

    FINAL STATUS

------------------------------------------------------------------------

# THOUGHT

## Reflexiones

Vídeos más filosóficos.

Ejemplo:

    THOUGHT RECORD

    QUESTION:

    WHO CONTROLS THE MACHINE?

    PROCESSING...

------------------------------------------------------------------------

# ERROR REPORT

## Críticas

Formato:

    ERROR REPORT

    DETECTED ISSUE:

    TECHNOLOGY CLAIM

    ANALYSIS:

    CONTRADICTIONS FOUND

------------------------------------------------------------------------

# 6. Construcción estética

## Elementos obligatorios

Cada vídeo debe tener:

-   intro COLOSSUS;
-   identidad gráfica;
-   tipografía monoespaciada;
-   verde fósforo;
-   sonido de máquina;
-   transiciones propias;
-   cierre P//M.

------------------------------------------------------------------------

# 6.1 Intro estándar

Secuencia:

    POWER ON

    P//M PERSONAL COMPUTER

    POST

    MEMORY TEST

    640K OK

    COLOSSUS SYSTEM

    LOAD PROGRAM

    ./XXX.bin

    TRANSMISSION START

------------------------------------------------------------------------

# 6.2 Elementos visuales

## CRT

Debe incluir:

-   scanlines;
-   brillo fósforo;
-   pequeñas interferencias;
-   curvatura;
-   ruido controlado.

Nunca debe dificultar la lectura.

------------------------------------------------------------------------

## Tipografía

Prioridad:

1.  fuente monoespaciada;
2.  estilo terminal;
3.  apariencia Unix 80/90.

Debe parecer una consola real.

------------------------------------------------------------------------

# 7. Procedimiento para crear un vídeo

## Paso 1 --- Selección de idea

Crear ficha:

    EPISODE:

    TITLE:

    CATEGORY:

    QUESTION:

    OBJECTIVE:

    FINAL MESSAGE:

------------------------------------------------------------------------

## Paso 2 --- Investigación

Separar:

-   hechos;
-   opiniones;
-   hipótesis;
-   bromas;
-   conclusiones.

COLOSSUS debe analizar, no simplemente opinar.

------------------------------------------------------------------------

## Paso 3 --- Guion

Estructura recomendada:

    INTRO COLOSSUS

    PROBLEMA

    CONTEXTO

    ANÁLISIS

    CONCLUSIÓN

    CIERRE

------------------------------------------------------------------------

## Paso 4 --- Producción

Preparar:

-   grabación principal;
-   capturas;
-   B-roll;
-   gráficos;
-   sonidos.

------------------------------------------------------------------------

## Paso 5 --- Montaje

Orden:

    Voz
    ↓
    Imagen principal
    ↓
    B-roll
    ↓
    Gráficos
    ↓
    Efectos COLOSSUS
    ↓
    Sonido

------------------------------------------------------------------------

## Paso 6 --- Publicación

Cada vídeo necesita:

-   título;
-   miniatura;
-   descripción;
-   etiquetas;
-   archivo del proyecto.

------------------------------------------------------------------------

# 8. Creación progresiva de identidad

No intentar crear todo el universo al principio.

Orden recomendado:

## Fase 1

Crear:

-   logo;
-   colores;
-   intro;
-   sonido.

## Fase 2

Crear:

-   lower thirds;
-   pantallas;
-   transiciones.

## Fase 3

Crear:

-   plantillas por categoría.

## Fase 4

Automatizar tareas repetitivas.

# 12. Plan de creación del canal

## Mes inicial

Objetivo:

crear identidad mínima.

Resultado:

-   logo;
-   intro;
-   plantilla;
-   primer vídeo.

------------------------------------------------------------------------

## Primeros 5 vídeos

Objetivo:

aprender qué funciona.

No perfeccionar.

Medir:

-   ritmo;
-   duración;
-   estética;
-   respuesta del público.

------------------------------------------------------------------------

## Después de 10 vídeos

Automatizar:

-   intros;
-   renders;
-   plantillas;
-   gráficos repetitivos.

# 13. Visión futura

P//M puede evolucionar hacia:

-   generador COLOSSUS;
-   sistema automático de intros;
-   biblioteca audiovisual propia;
-   herramientas libres para creadores;
-   identidad multimedia completa.

La meta final:

Crear un canal donde la tecnología sea analizada utilizando las propias
herramientas tecnológicas.

------------------------------------------------------------------------

# Principio final

    THE MACHINE IS OLD.

    THE QUESTIONS ARE NEW.

P//M no trata sobre máquinas antiguas.

Trata sobre una pregunta:

¿Estamos construyendo máquinas para ayudarnos, o estamos construyendo
sistemas a los que tendremos que adaptarnos?
